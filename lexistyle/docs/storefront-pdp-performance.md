# Storefront PDP 성능 구조

## 분석

상품 상세 요청에서 다음 병목을 확인했다.

1. 상품 단건 조회가 `products` 전체를 가져온 뒤 애플리케이션에서 slug를 검색했다.
2. 연관상품이 전체 상품 목록을 다시 읽었다.
3. 구매 옵션이 고객 요청 중 CJ API를 호출했다. Vercel 인스턴스 메모리 캐시는 콜드 스타트와 인스턴스 교체 때 재사용되지 않는다.
4. PDP 문서 조회가 상품과 카탈로그를 직렬 조회하고, 폴백은 PDP 문서 200개를 전송받아 검색했다.
5. 리뷰가 상품 id 조회 후 리뷰를 조회해 DB 왕복이 직렬로 발생했다.

## 구현 규칙

- 고객 상품 상세 경로는 CJ API를 호출하지 않는다.
- 옵션 Source of Truth는 `catalog_index.raw_meta.variants`다. CJ 옵션은 Import 또는 Export 준비 단계에서 이 필드에 저장한다.
- 상품은 slug 단건 쿼리, 연관상품은 카테고리별 `LIMIT`, 리뷰는 상품 조인 한 번으로 읽는다.
- 상품과 PDP 문서 참조는 조인 한 번으로 읽는다.
- 옵션 쿼리는 `Suspense` 경계 안에서 실행해 본문 스트리밍을 막지 않는다.
- 옵션 캐시가 없으면 선택 UI를 숨긴다. 고객 요청에서 공급처로 폴백하지 않는다.

## 운영 검증

배포 전후 동일 상품을 콜드/웜 요청으로 각각 2회 이상 측정한다. 목표는 웜 HTML 응답 1.5초 이내이며, CJ 장애 중에도 상품 본문이 정상 응답해야 한다.
