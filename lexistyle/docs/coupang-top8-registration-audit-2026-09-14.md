## 확인 및 수정

- 최초 조회: 8개 모두 DENIED(승인반려). 모두 구비서류 다운로드 실패, 231은 검색태그 20자 초과도 포함.
- 카테고리 메타와 현재 배송 유형을 대조했다. 현재 일반배송 등록에 적용되지 않는 구매대행 인보이스 첨부를 제거했다. 필수 서류를 대신 만들거나 승인 요건을 변경하지 않았다.
- 동일 반품지 코드의 실제 WING 주소를 조회하여 깨진 한글 주소와 반품지명을 수정했다.
- 초과 검색태그를 제거했다.
- 기존 sellerProductId를 유지하고 requested=false로 수정 저장했다. 신규 중복 상품은 만들지 않았다.
- 상세한 수정 및 재조회 결과는 로컬 `tmp/coupang-repair-verified.json`에 보관한다. 원본 응답에는 사업자 연락처 등이 포함되어 저장소에 추가하지 않는다.

## 판매 재승인 전 미해결 사항

- 공급처 API가 `Your API access has been disabled` 오류를 반환한다. CJ 계정 APIStores에서 재활성화 필요.
- 기존 단일 옵션의 색상/사이즈가 모두 FREE이며, 실제 공급처 SKU와 연결되지 않았다.
- 공급처 옵션별 재고, 원가, 해당 PDP와 옵션 사진의 일치, 고시정보를 검증해야 한다. 카탈로그의 기본 stock=10은 검증된 창고 재고로 사용할 수 없다.
- 현재 8개 판매가가 모두 같으므로 공급처 원가 및 프로젝트 가격 정책으로 재계산해야 한다. 승인받기 위해 임의의 가격·재고·소재를 채우면 안 된다.
- 해외구매대행으로 운영할 경우 해당 배송 유형, 해외 출고지, 통관정보 및 필요 서류를 실제 운영 방식에 맞게 검증해야 한다.

## 코드 보완

- 검색태그 길이·개수 및 중복 정리.
- 구비서류 공개 다운로드 가능 여부, 형식, 빈 파일, 5MB 초과 사전검사.
- 실제 SKU·재고·필수 구매옵션이 없으면 등록 차단. 입력된 옵션별 가격과 재고를 전송.
- 반품지 코드의 실제 등록 주소를 조회하여 사용.
- 원래 가격에 임의 15%를 더하는 처리 제거.

## 재개 순서

1. 공급처 API 복구 후 위 8개 externalId의 실제 상세·옵션·재고 조회.
2. 상품별 PDP/옵션/가격/고시/배송 유형을 교차 검증하고 수정 전문 준비.
3. 기존 sellerProductId를 수정한 뒤 승인 요청. 기존 승인 상품을 재생성하지 않는다.
4. 재조회하여 SAVED/심사중/승인완료/반려를 구분하고, 반려 시 상태변경 이력 확인.

참조: [상품 수정 API](https://developers.coupang.com/ko/api/products/modify-product), [카테고리 메타](https://developers.coupang.com/ko/api/categories/category-metadata-query).
