# 가락한상 — Neon Auth(네온오스) 로그인 연동 가이드

> **대상**: 가락한상 쇼핑몰 (lexistyle 기반) · **작성일**: 2026-10-22
> **현재 상태**: 데모 로그인(DEMO_LOGIN)으로 전체 플로우 검증 완료, 실 Neon Auth 연동 대기

---

## 1. 현재 인증 구조

| 경로 | 역할 |
|---|---|
| `src/lib/auth/server.ts` | `NEON_AUTH_BASE_URL` + `NEON_AUTH_COOKIE_SECRET` 설정 시 Neon Auth 활성화 (`authConfigured`) |
| `src/app/[lng]/api/auth/[...path]/route.ts` | Neon Auth 핸들러 패스스루 — 미설정 시 "세션 없음"으로 무해 응답 |
| `src/app/[lng]/auth/sign-up` | 회원가입 (Google 소셜) — 가락한상 브랜딩 적용 완료 |
| `src/app/[lng]/auth/sign-in` | 로그인 |
| `src/app/[lng]/api/auth/demo` | 데모 로그인 (DEMO_LOGIN=1일 때만) — 서명 쿠키 발급 |
| `src/lib/auth/admin.ts` | `requireSession()` — 데모 쿠키 → 자체 Google 세션 → Neon 세션 순으로 판정 |

## 2. 실 Neon Auth 연동 절차 (5분)

1. [neon.tech](https://neon.tech) 가입 → 프로젝트 생성 (무료 플랜 가능)
2. 프로젝트 대시보드 → **Auth** 탭 → Neon Auth 활성화
3. Auth 탭에서 제공되는 **Auth Base URL** 복사
4. 시크릿 생성: `openssl rand -base64 32` (또는 PowerShell 랜덤 32바이트 base64)
5. `.env.local`(로컬) / Vercel Project Settings → Environment Variables(배포)에 추가:
   - `NEON_AUTH_BASE_URL=https://<프로젝트>.neon.tech` (1단계의 Auth URL)
   - `NEON_AUTH_COOKIE_SECRET=<32바이트 랜덤>`
6. 서버 재시작 → `/auth/sign-up`에서 Google 회원가입 활성화

> 연동 후에는 `DEMO_LOGIN=1`을 제거(또는 0)해 데모 로그인을 잠그세요.

## 3. 검증 완료된 플로우 (데모 세션 기준, 2026-10-22)

| 단계 | 결과 |
|---|---|
| 회원가입/로그인 페이지 렌더 | ✓ 가락한상 브랜딩, Google 버튼 |
| 세션 로그인 | ✓ 데모 세션 발급 → 마이 페이지에 사용자 표시 |
| 위시리스트 (로그인 필요 기능) | ✓ POST 200 — 쿠키 기반 메모리 폴백(더미 모드) |
| 장바구니 | ✓ 담기 1건 55,000원 |
| 주문 + 결제 | ✓ `/api/checkout` mock PG — 주문 생성 + `paymentRef` 발급 |
| 결제 완료 페이지 | ✓ "ORDER CONFIRMED" + 결제번호 표시 |
| 주문 내역 페이지 | ✓ 렌더 (주문 목록은 DB 연결 시 실제 표시) |

> 검증 스크립트: `scripts/verify-auth.mjs` — 재실행: `node scripts/verify-auth.mjs`

## 4. 실결제(PG) 활성화 조건

| PG | 필요 환경변수 | 상태 |
|---|---|---|
| 토스페이먼츠 | `TOSS_SECRET_KEY` + `NEXT_PUBLIC_TOSS_CLIENT_KEY` | 미설정 |
| 다날 | `DANAL_SECRET_KEY` + `DANAL_MERCHANT_ID` + `DANAL_CLIENT_KEY` | 미설정 |
| Stripe | `STRIPE_SECRET_KEY` | 미설정 |
| mock | 없음 (테스트 전용, 항상 사용 가능) | **활성** |

키가 없으면 자동으로 mock PG로 폴백되어 결제 흐름이 항상 이어집니다.
